# FlowSpeak Deployment Guide

## 1. Prerequisites

- **SDK:** .NET 10.0 SDK
- **Database:** SQL Server 2022+ or Azure SQL
- **Orchestration:** Docker (for n8n integration)
- **AI:** Groq API Key

## 2. Environment Configuration

Create a `.env` file in the root or update `src/FlowSpeak.Api/appsettings.json`:

| Key                                   | Description                            |
| ------------------------------------- | -------------------------------------- |
| `ConnectionStrings:DefaultConnection` | SQL Server Connection String           |
| `GROQ_API_KEY`                        | API Key for Groq Cloud                 |
| `JWT_SECRET`                          | 32+ character string for token signing |
| `PROD_ADMIN_USERNAME`                 | Initial admin username for seeding     |
| `PROD_ADMIN_PASSWORD`                 | Initial admin password for seeding     |

## 3. Database Setup

The project uses Entity Framework Core with automatic seeding.

1. Ensure your connection string in `appsettings.json` is correct.
2. The application will run `context.Database.MigrateAsync()` on startup via `DbInitializer`.

## 4. Admin Access

Because hardcoded demo accounts have been removed for security (`DbInitializer.cs`), the first administrator must be provisioned via environment variables or the registration endpoint.

- **Initial Role:** Admin
- **Default Seeded Products:** Access SKUs like `DELL-XPS15` and `MAC-MP16` for testing.

## 5. Running the Project

### Backend (API)

```bash
cd src/FlowSpeak.Api
dotnet restore
dotnet run
```

### n8n Workflows

1. Start n8n (via Docker).
2. Import JSON workflows from the `/n8n-workflows` directory.
3. Update the webhook URL in `appsettings.json` to point to your n8n instance.

## 6. Endpoints & Features

- **Telemetry Logs:** `GET /api/telemetry/logs` (Requires Admin Role)
- **AI Action Dispatch:** `POST /api/action` (Accepts natural language intent)
- **Stock Management:** Managed via `ProductService` with Optimistic Concurrency (`RowVersion`).

## 7. Troubleshooting

- **Concurrency Errors:** If you receive a "User retry" error during stock updates, it means a `DbUpdateConcurrencyException` was caught. This is expected behavior to prevent race conditions.
- **Empty Logs:** Telemetry logs will be empty until the first AI command is processed and saved to the `AI_CommandLogs` table.
- **Auth Failures:** Ensure the `RefreshTokenHash` in the database matches the SHA256 hash of the token held in the client-side cookie.
